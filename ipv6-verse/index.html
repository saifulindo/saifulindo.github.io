12.1 Masalah IPv4

Kebutuhan untuk IPv6

Anda sudah tahu bahwa IPv4 kehabisan alamat. Itulah mengapa Anda perlu belajar tentang IPv6. IPv6 dirancang untuk menjadi penerus IPv4. IPv6 memiliki ruang alamat 128-bit yang lebih besar, menyediakan 340 undecillion (yaitu, 340 diikuti oleh 36 nol) kemungkinan alamat. Namun, IPv6 lebih dari sekadar alamat yang lebih besar.

Ketika IETF memulai pengembangan penerus IPv4, IETF menggunakan kesempatan ini untuk memperbaiki keterbatasan IPv4 dan memasukkan peningkatan. Salah satu contohnya adalah Internet Control Message Protocol versi 6 (ICMPv6), yang mencakup resolusi alamat dan autokonfigurasi alamat yang tidak ditemukan di ICMP untuk IPv4 (ICMPv4).

Menipisnya ruang alamat IPv4 telah menjadi faktor motivasi untuk pindah ke IPv6. Ketika Afrika, Asia, dan wilayah lain di dunia menjadi lebih terhubung ke internet, tidak ada cukup alamat IPv4 untuk mengakomodasi pertumbuhan ini. Seperti yang ditunjukkan pada gambar, empat dari lima RIR telah kehabisan alamat IPv4.

IPv4 memiliki maksimum teoritis 4,3 miliar alamat. Alamat pribadi dalam kombinasi dengan Network Address Translation (NAT) telah berperan dalam memperlambat penipisan ruang alamat IPv4. Namun, NAT bermasalah untuk banyak aplikasi, menciptakan latensi, dan memiliki keterbatasan yang sangat menghambat komunikasi peer-to-peer.

Internet of Things (IoT)

Internet saat ini sangat berbeda dari internet beberapa dekade terakhir. Internet berkembang menjadi Internet of Things (IoT). Tidak lagi satu-satunya perangkat yang mengakses internet adalah komputer, tablet, dan smartphone. Perangkat masa depan yang dilengkapi sensor dan siap internet akan mencakup segala hal mulai dari mobil dan perangkat biomedis, hingga peralatan rumah tangga dan ekosistem alami.

Dengan populasi internet yang meningkat, ruang alamat IPv4 yang terbatas, masalah dengan NAT dan IoT, saatnya telah tiba untuk memulai transisi ke IPv6.

Ko-eksistensi (Berdampingan) IPv4 dan IPv6

Tidak ada tanggal khusus untuk pindah ke IPv6. Baik IPv4 dan IPv6 akan hidup berdampingan dalam waktu dekat dan transisi akan memakan waktu beberapa tahun. IETF telah menciptakan berbagai protokol dan alat untuk membantu administrator jaringan memigrasikan jaringan mereka ke IPv6. Teknik migrasi dapat dibagi menjadi tiga kategori:

  • Dual Stack: Memungkinkan IPv4 dan IPv6 untuk hidup berdampingan di segmen jaringan yang sama. Perangkat Dual Stack menjalankan tumpukan protokol IPv4 dan IPv6 secara bersamaan.
  • Tunneling: Metode pengangkutan paket IPv6 melalui jaringan IPv4. Paket IPv6 dienkapsulasi di dalam paket IPv4.
  • Translation (NAT64): Memungkinkan perangkat yang mendukung IPv6 untuk berkomunikasi dengan perangkat yang mendukung IPv4. Paket IPv6 diterjemahkan ke paket IPv4 dan sebaliknya.

12.2 Representasi Alamat IPv6

Format Pengalamatan IPv6

Alamat IPv6 memiliki panjang 128 bit dan ditulis sebagai string nilai heksadesimal. Setiap empat bit diwakili oleh satu digit heksadesimal; untuk total 32 nilai heksadesimal. Alamat IPv6 tidak peka huruf besar-kecil.

Format yang lebih disukai untuk menulis alamat IPv6 adalah x:x:x:x:x:x:x:x, dengan setiap “x” terdiri dari empat nilai heksadesimal. Istilah tidak resmi "hextet" digunakan untuk merujuk ke segmen 16 bit (atau empat nilai heksadesimal) ini.

Contoh alamat IPv6 dalam format preferred (lengkap): 2001:0db8:0000:1111:0000:0000:0000:0200

Aturan 1 – Abaikan Angka Nol Awal (Leading Zeros)

Aturan pertama untuk mengurangi notasi adalah menghilangkan 0 (nol) di awal (leading zeros) di hextet mana pun.

  • 01ab dapat direpresentasikan sebagai 1ab
  • 09f0 dapat direpresentasikan sebagai 9f0
  • 00ab dapat direpresentasikan sebagai ab
  • 0000 dapat direpresentasikan sebagai 0

Aturan ini hanya berlaku untuk awalan 0, BUKAN pada akhiran 0. (Misal, abc0 tetap abc0).

Contoh Penerapan Aturan 1:

TypeAlamat
Preferred 2001:0db8:0000:1111:0000:0000:0000:0200
Tanpa 0 Awal 2001:db8:0:1111:0:0:0:200
Preferred fe80:0000:0000:0000:0123:4567:89ab:cdef
Tanpa 0 Awal fe80:0:0:0:123:4567:89ab:cdef

Aturan 2 – Titik Dua Ganda (Double Colon ::)

Aturan kedua adalah bahwa titik dua ganda (::) dapat menggantikan satu string tunggal yang berdekatan dari satu atau lebih hextet yang berisi semua nol.

Titik dua ganda (::) hanya dapat digunakan satu kali dalam sebuah alamat. Jika digunakan lebih dari sekali, alamatnya akan ambigu (tidak jelas di mana harus meletakkan nolnya).

Praktik Terbaik: Jika sebuah alamat memiliki lebih dari satu string nol (misal 2001:0:0:abcd:0:0:0:1), gunakan :: pada string terpanjang. Jika stringnya sama panjang (misal 2001:0:0:ab:cd:0:0:1), :: harus digunakan pada string pertama.

Contoh Penerapan Aturan 1 dan 2 (Format Terkompresi):

TypeAlamat
Preferred fe80:0000:0000:0000:0123:4567:89ab:cdef
Aturan 1 fe80:0:0:0:123:4567:89ab:cdef
Aturan 2 (Kompres) fe80::123:4567:89ab:cdef
Preferred 2001:0db8:0000:1111:0000:0000:0000:0200
Aturan 1 2001:db8:0:1111:0:0:0:200
Aturan 2 (Kompres) 2001:db8:0:1111::200
Preferred 0000:0000:0000:0000:0000:0000:0000:0001
Aturan 1 0:0:0:0:0:0:0:1
Aturan 2 (Kompres) ::1

12.3 Jenis Alamat IPv6

Unicast, Multicast, Anycast

Ada tiga kategori besar alamat IPv6:

  • Unicast: Mengidentifikasi interface secara unik. Paket dikirim ke satu interface.
  • Multicast: Digunakan untuk mengirim satu paket ke beberapa tujuan (grup multicast).
  • Anycast: Alamat unicast yang dapat ditetapkan ke beberapa perangkat. Paket dikirim ke perangkat *terdekat* yang memiliki alamat tersebut.

Tidak seperti IPv4, IPv6 tidak memiliki alamat broadcast. Fungsinya digantikan oleh alamat multicast all-node.

Prefix Length IPv6

IPv6 tidak menggunakan subnet mask. IPv6 menggunakan Prefix Length (notasi CIDR /) untuk menunjukkan bagian network. Prefix length bisa berkisar dari 0 hingga 128. Untuk LAN, prefix length yang direkomendasikan adalah /64.

Jenis Alamat Unicast IPv6

Perangkat IPv6 biasanya memiliki dua alamat unicast:

  1. Global Unicast Address (GUA): Mirip dengan alamat IPv4 publik. Alamat ini unik secara global dan dapat dirutekan di internet. (Contoh: 2001:db8:acad::/48).
  2. Link-local Address (LLA): Diperlukan untuk setiap perangkat IPv6. Hanya digunakan untuk berkomunikasi dengan perangkat lain di link (subnet) yang sama. Router tidak akan meneruskan paket LLA.

GUA IPv6

GUA adalah alamat yang setara dengan IPv4 publik. Saat ini, hanya GUA yang dimulai dengan 001 (atau 2000::/3) yang sedang dialokasikan. GUA memiliki tiga bagian:

  • Global Routing Prefix: Bagian network yang ditetapkan oleh ISP ke pelanggan (Misal, /48).
  • Subnet ID: Area yang digunakan oleh organisasi untuk mengidentifikasi subnet internal (Misal, 16 bit jika prefix /48 dan Interface ID /64).
  • Interface ID: Setara dengan bagian host di IPv4 (Selalu disarankan 64 bit).

LLA IPv6

LLA memungkinkan perangkat berkomunikasi di link lokal (subnet) yang sama, bahkan tanpa GUA. Setiap interface IPv6 *harus* memiliki LLA.

LLA selalu berada dalam rentang fe80::/10. Router tidak akan meneruskan paket dengan LLA sebagai sumber atau tujuan.

Host menggunakan LLA dari router lokal sebagai default gateway.

12.4 Konfigurasi Statis GUA dan LLA

12.4.1 Konfigurasi Statis GUA pada Router

Perintah Cisco IOS untuk mengkonfigurasi GUA IPv6 pada interface adalah ipv6 address [ipv6-address]/[prefix-length].

R1(config)# interface gigabitethernet 0/0/0
R1(config-if)# ipv6 address 2001:db8:acad:1::1/64
R1(config-if)# no shutdown
R1(config-if)# exit
R1(config)# interface gigabitethernet 0/0/1
R1(config-if)# ipv6 address 2001:db8:acad:2::1/64
R1(config-if)# no shutdown

12.4.3 Konfigurasi Statis LLA

Mengonfigurasi LLA secara manual disarankan pada router agar mudah dikenali (misal, fe80::1) sebagai default gateway. Perintahnya adalah ipv6 address [lla-address] link-local.

R1(config)# interface gigabitethernet 0/0/0
R1(config-if)# ipv6 address fe80::1:1 link-local
R1(config-if)# exit
R1(config)# interface gigabitethernet 0/0/1
R1(config-if)# ipv6 address fe80::2:1 link-local

12.4.2 Konfigurasi Statis GUA pada Host Windows

Mengonfigurasi GUA pada host Windows mirip dengan IPv4. Anda memasukkan alamat IPv6, prefix length, dan default gateway (yang biasanya adalah LLA router).

12.5 Pengalamatan Dinamis untuk GUA

12.5.1 Pesan RS dan RA

Perangkat dapat memperoleh GUA secara dinamis melalui pesan ICMPv6. Proses ini melibatkan dua pesan:

  • Router Solicitation (RS): Dikirim oleh host yang meminta informasi pengalamatan.
  • Router Advertisement (RA): Dikirim oleh router setiap 200 detik (atau sebagai balasan RS) untuk memberi tahu host cara mendapatkan alamat.

Agar router dapat mengirim RA, perintah global ipv6 unicast-routing harus diaktifkan.

Pesan RA menyarankan salah satu dari tiga metode:

12.5.2 Metode 1: SLAAC (Stateless Address Autoconfiguration)

Perangkat membuat GUA-nya sendiri. Pesan RA menyediakan Prefix (64 bit pertama), dan perangkat membuat Interface ID (64 bit terakhir) sendiri. Perangkat juga menggunakan LLA router (alamat sumber RA) sebagai default gateway.

12.5.3 Metode 2: SLAAC dengan DHCPv6 Stateless

Pesan RA memberi tahu perangkat:

  1. Gunakan SLAAC untuk membuat GUA dan Default Gateway.
  2. Hubungi server DHCPv6 "Stateless" untuk info tambahan (seperti alamat server DNS).

12.5.4 Metode 3: DHCPv6 Stateful (No SLAAC)

Pesan RA memberi tahu perangkat:

  1. Gunakan LLA router sebagai Default Gateway.
  2. Hubungi server DHCPv6 "Stateful" untuk meminta GUA dan semua info lainnya (termasuk DNS).

(Ini adalah metode yang paling mirip dengan DHCP pada IPv4).

12.5.5-12.5.7 Proses EUI-64 vs Dihasilkan secara Acak

Jika menggunakan SLAAC (Metode 1 atau 2), perangkat harus membuat Interface ID 64-bit sendiri. Ada dua cara:

  1. Proses EUI-64: Menggunakan alamat MAC 48-bit dari perangkat, menyisipkan fffe di tengah, dan membalik (flip) bit ke-7. Ini unik tetapi dapat menimbulkan masalah privasi.
  2. Dihasilkan secara Acak (Randomly Generated): Sebagian besar sistem operasi modern (termasuk Windows) sekarang menghasilkan Interface ID acak untuk GUA untuk melindungi privasi.

12.6 Pengalamatan Dinamis untuk LLA

12.6.1-12.6.3 LLA Dinamis

Semua perangkat IPv6 harus memiliki LLA. LLA dapat dibuat secara dinamis (menggunakan EUI-64 atau angka acak) atau dikonfigurasi secara statis.

Router Cisco secara otomatis membuat LLA menggunakan EUI-64 segera setelah interface diaktifkan untuk IPv6 (misalnya, saat GUA dikonfigurasi).

Sistem operasi, seperti Windows, biasanya akan menggunakan metode yang sama (misal, angka acak) untuk GUA yang dibuat SLAAC dan LLA yang ditetapkan secara dinamis.

12.6.4 Verifikasi Konfigurasi IPv6

Gunakan perintah show ipv6 interface brief untuk melihat alamat GUA dan LLA pada semua interface.

12.7 Alamat Multicast IPv6

Alamat multicast digunakan untuk mengirim satu paket ke beberapa tujuan. Alamat multicast IPv6 memiliki prefix ff00::/8.

Alamat IPv6 Multicast Well-Known

Ini adalah alamat yang dicadangkan untuk grup perangkat tertentu. Dua grup yang paling umum adalah:

  • ff02::1 (All-node multicast group): Semua perangkat IPv6-enabled bergabung dengan grup ini. Ini adalah pengganti broadcast IPv4. Pesan RA dari router dikirim ke alamat ini.
  • ff02::2 (All-router multicast group): Semua router IPv6 bergabung dengan grup ini. Pesan RS dari host dikirim ke alamat ini untuk "menemukan" router.

Solicited-Node Alamat IPv6 Multicast

Ini adalah jenis alamat multicast khusus yang digunakan untuk menggantikan ARP di IPv4. Setiap perangkat membuat alamat solicited-node yang unik untuk GUA dan LLA-nya. Ketika sebuah host perlu menemukan alamat MAC untuk alamat IPv6 tertentu, ia mengirim paket ke alamat solicited-node, bukan ke semua node (broadcast).

Keuntungannya adalah hanya perangkat target yang akan "mendengarkan" alamat multicast ini, sehingga mengurangi beban pemrosesan pada host lain di jaringan.

12.8 Subnet Jaringan IPv6

Subnet Menggunakan Subnet ID

IPv6 dirancang dengan mempertimbangkan subnetting. Kita tidak perlu "meminjam" bit dari bagian host seperti di IPv4. Kita menggunakan Subnet ID yang sudah ada di dalam struktur GUA.

Jika ISP memberi Anda Global Routing Prefix /48, dan Anda menggunakan Interface ID /64 (sesuai rekomendasi), Anda memiliki sisa 16 bit untuk Subnet ID (64 - 48 = 16).

Subnet ID 16-bit ini memberi Anda:

  • 65.536 subnet (2^16)

Dan Interface ID 64-bit memberi Anda:

  • 18 Triliun host per subnet (2^64)

Subnetting IPv6 sangat mudah. Tidak perlu konversi biner. Cukup hitung dalam heksadesimal di dalam field Subnet ID.

Contoh Subnetting IPv6

Jika organisasi Anda diberi prefix 2001:db8:acad::/48, Anda dapat membuat subnet /64 dengan menambah hextet ke-4 (Subnet ID):

  • Subnet 1: 2001:db8:acad:0000::/64 (atau ...:0::/64)
  • Subnet 2: 2001:db8:acad:0001::/64 (atau ...:1::/64)
  • Subnet 3: 2001:db8:acad:0002::/64 (atau ...:2::/64)
  • ...
  • Subnet 10: 2001:db8:acad:0009::/64 (atau ...:9::/64)
  • Subnet 11: 2001:db8:acad:000a::/64 (atau ...:a::/64)
  • Subnet 12: 2001:db8:acad:000b::/64 (atau ...:b::/64)
  • ...
  • Subnet Terakhir: 2001:db8:acad:ffff::/64

Alokasi Subnet IPv6

Tugas administrator adalah merancang skema alokasi yang logis. Tidak perlu khawatir tentang pemborosan alamat. Bahkan link serial point-to-point antara router tetap menggunakan /64.
